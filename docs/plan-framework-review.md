# 试点复盘方案：memo + today 迁移后评估

- 日期：2026-08-17
- 状态：**已完成**（结论见 ADR-011「试点评估检查点」小节；执行结果：路径 B，试点三候选 dev）
- 性质：**只读评估，不写任何代码、不动任何数据**（失败无回滚问题）

## 一句话

已迁移 2 个试点模块（备忘、今日计划），按协议到达评估点——停下来检查框架健不健康、渲染层该不该做、下一步迁谁；30-60 分钟出结论。

## 背景：为什么现在做

1. **迁移不产生用户可感知价值**——它是"看不见的换水管"。2 个试点已把工厂核心模式验证完，继续无脑迁移第 3 个，收益递减。
2. **协议里设计好的检查点**：当初约定"VisualEngine 等 2-3 个模块迁移后证明重复需要才进框架"，现在正好是回答这个问题的时点。
3. **防止过度设计**（AGENTS.md 停止条件）：万一工厂开始膨胀/特判，继续迁只会越积越重。

## 查什么（4 项）

### 1. 工厂健康体检（停止条件核对）
- **查**：ModuleFactory.js 现状——有没有被逼出 if/else 特判（如"memo 走 A、today 走 B"这种分支）？文件行数与 v0.1.1 相比膨胀多少？新增能力是否都是"配置级"（一个开关/字段）而非"逻辑级"（改内部流程）？
- **算"过"**：无特判、扩展全部配置化、新增行为都有契约测试锁定。
- **算"不过"**：出现按模块名分叉的逻辑 → 先修工厂，不硬迁。

### 2. 工厂能力使用率盘点
- **查**：已上线能力清单（validate/normalize/freeze、add/update/remove/query、move、prepend、timeField、orderField、customRender、EVENT 订阅、撤销栈）逐项核对——memo/today 谁在用？契约测试是否锁定？
- **产出**：一份"用 / 未用"清单。未用的能力思考去留：第一版框架克制，用不上的不加维护负担。
- **算"过"**：主要能力都有真实消费方或测试锁定。

### 3. 渲染重复度评估（VisualEngine 阈值判断）
- **查**：对比 memo.js 与 today.js 的渲染代码，找出重复出现的惯用法（预计 3-5 类，如：数组→列表→esc→innerHTML、空态提示、按钮组、删除确认+撤销）。
- **判断标准**（协议原文）："至少 2-3 个模块重复需要才进框架"——现在恰好 2 个模块，重复度是否**显著到值得抽层**（不是"有点像"而是"复制粘贴改字段"）。
- **产出**：重复惯用法清单 + 建议（VisualEngine 做哪 2-3 个渲染原语 / 或继续 customRender 复制粘贴）。
- **算"过"**（值得做 VisualEngine）：存在多处逐字级重复。
- **算"不过"**：只是"风格相似" → 继续业务层复制，框架不加层。

### 4. 缺口清单分类
- **查**：两次迁移中工厂暴露的缺口（已知：memo 需要 prepend/timeField，today 需要 orderField/move——都走了"配置级扩展"）。
- **分类**：新暴露的缺口，哪些是**多个模块都会要**（通用 → 候选工厂 v0.1.3），哪些是**单模块特例**（→ 留业务层，不进框架）。
- **产出**：分类后的缺口清单。

## 结果怎么走（决策树）

| 检查结果 | 建议路径 |
|---|---|
| 工厂健康 + 渲染重复显著 | **路径 A**：VisualEngine 评估 → 再迁一个复杂渲染模块压测 |
| 工厂健康 + 渲染重复不显著 | **路径 B**（推荐默认）：迁试点三 dev（速查手册，页面薄、风险小） |
| 工厂不健康 | **路径 C**：先修工厂（列问题清单）再继续 |
| 出现多个通用缺口 | **路径 D**：先做工厂 v0.1.3（缺口补齐）再迁下一个 |
| 结论模糊、无明确方向 | **路径 E**：暂停框架，转产品改进（问用户日常痛点） |
