# ADR-004：PWA 离线与缓存版本管理

- 状态：已采纳
- 背景：应用定位"断网亦可使用"，但静态资源缓存策略一旦失误会造成"老用户永远命中旧版"或"离线打不开"两类事故；个人项目无运维人力，必须自动化。
- 决策：
  1. 缓存策略分层：**导航请求 Network First**（有网拿新版并回写缓存，刷新即更新；离线回退 index.html 缓存副本）；**静态资源 Cache First**（命中直接返回，未命中回源并写缓存）。
  2. 版本机制：`CACHE = 'sonder-vN'`，install 预缓存全部 ASSETS（35 项），activate 清理旧版本缓存；sw 更新采用 skipWaiting + clients.claim 立即接管。
  3. **sync-sw 自动化**（scripts/sync-sw.js）：index.html 是资源清单唯一真源，从中解析脚本/样式生成 ASSETS 写入 sw.js；检测到**清单变化或内容指纹（ASSET_SIG，全清单文件 sha256 前 12 位）变化**时自动递增 CACHE 版本；`--force` 提供主动刷新逃生门。
  4. 幂等保证：内容未变时重复运行 sync-sw 不产生 diff（已有测试 + 人工验证）。
- 理由：内容指纹解决"只改代码忘了升版"的根因——老缓存失效条件从"清单新增"扩展到"任何文件内容变化"；版本号单一递增源避免多部署位漂移。
- 代价：每次改首页/脚本/样式必须跑 sync-sw（README 有说明；scripts.test.js 有同步性断言）；sw.js 自身注释与 sig 行不参与指纹（自指避免）。
