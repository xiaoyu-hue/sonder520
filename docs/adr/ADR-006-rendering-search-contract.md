# ADR-006：渲染模型与搜索契约

- 状态：已采纳；局部更新改造评估中
- 背景：无框架下各模块自持渲染：store 变更事件 → 模块 render() 全量重建 `#content` innerHTML。全局搜索是高频交互路径。
- 决策与现状：
  1. 页面渲染：模块级 `render(ctx)` 全量重建（简单、可预测、可测试），事件委托挂载在容器级，render 后自动恢复交互。
  2. 全局搜索（search.js）：
     - 结果面板每次击键全量重建当前匹配列表（索引 localStorage 缓存 + 预过滤，数据量小可接受）；**不做防抖**——搜索测试以同步派发 `input` 事件 + 立即断言为契约（ADR-003 原则：测试契约为先）。
     - 跳转高亮用 `waitRendered` 条件轮询（40ms × 1s 超时）+ **导航失效守卫**：等待期间用户切到其他页面则静默放弃，不高亮错页。
  3. 性能审计（2026-08）指出全量重渲染是最大潜在瓶颈（24+ 赋值点），已做：全局 defer 消首屏阻塞；缓解项（局部更新/深度克隆收敛）按收益风险比缓修。
- 代价：全量重建在数据量小（单机个人）场景无感知；表格/长列表模块（selfmedia 500+ 帖）在极端堆量下可能卡顿，演进方向为"列表容器局部更新 + 渲染微任务批量合并"。
